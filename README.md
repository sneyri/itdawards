# ITD Awards

Локальный прототип интернет-премии сообщества ITD. Каталог, номинанты, голоса и результаты хранятся в PostgreSQL. Express отдаёт API и сборку React/Vite из `client/dist`. Исходный дизайн — [itd-awards-2026](https://github.com/kirillsql1kaa11/itd-awards-2026/tree/6a7b56d).

## Запуск на Windows

Нужны Node.js 24 и запущенный PostgreSQL. Прототип проверен на Node.js 24.14.0 и PostgreSQL 18.3.

1. Создайте пустую базу `itd_awards` через pgAdmin или командой `createdb -h 127.0.0.1 -U postgres itd_awards`. Если база уже существует, используйте её. Пользователю приложения нужны права на создание таблиц в схеме базы.
2. В PowerShell из корня проекта установите зависимости и подготовьте конфигурацию.

   ```powershell
   npm.cmd ci --prefix client
   npm.cmd run build --prefix client
   Set-Location server
   npm.cmd ci
   ```

3. В `server/.env` укажите свои `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` и `DB_NAME`. `PORT` задаёт порт HTTP.
4. Из каталога `server` создайте таблицы, загрузите каталог номинаций и запустите приложение.

   ```powershell
   npm.cmd run db:init -- --catalog
   npm.cmd start
   ```

5. Если в `server/.env` задан `PORT=5000`, откройте [http://localhost:5000](http://localhost:5000). Без `PORT` сервер слушает порт 3000. Для входа открывайте сайт по адресу из `PUBLIC_ORIGIN`.

`npm.cmd run db:init` создаёт только схему. Флаг `--catalog` добавляет текущие номинации и номинантов из `server/database/catalog.sql`. Прежние демономинации и их голоса остаются в архиве и скрыты на сайте. Повторный импорт добавляет только недостающие записи. Для пустой учебной базы можно отдельно использовать `--seed`.

## Локальный предпросмотр предложений из Telegram

Из каталога `server` выполните команды ниже. Для импорта нужен Python 3 и права на создание базы `itd_awards_bot_preview` при первом запуске.

```powershell
npm.cmd run db:bot-preview -- 'C:\Users\Sneyr\Documents\ITD_Awards'
npm.cmd run start:bot-preview
```

Предпросмотр использует порт из `.env`. Если на нём уже запущен обычный экземпляр сайта, остановите его или задайте другой порт через `$env:PORT`. Скрипт читает `awards.db` и описания из `config.py`, переносит до пяти популярных предложений на номинацию и открывает тестовое голосование за них. Голоса хранятся в базе предпросмотра. При повторном импорте номинации с голосами сохраняют свой список кандидатов. `npm.cmd start` запускает обычный каталог из базы `DB_NAME`.

Для разработки запустите API и выполните `npm.cmd run dev --prefix client` из корня проекта. Vite перенаправляет запросы к API на порт `5000`, другой порт можно указать в `$env:API_PORT`.

## Анонимное голосование

При `VOTING_MODE=anonymous` пользователю достаточно выбрать номинанта и сохранить голос. При первом голосе браузер решает фоновую проверку ALTCHA. Сервер проверяет решение и выдаёт подписанную cookie. Повтор решения выдаёт тот же ID. Голоса этого браузера видны в разделе «Мой голос». Для браузерной проверки нужен HTTPS или localhost.

Задайте `ANONYMOUS_VOTER_SECRET` в `server/.env`. Получить случайное значение можно командой `node -p "require('node:crypto').randomBytes(32).toString('hex')"`. Сохраняйте секрет на весь период голосования. Сервер ограничивает количество запросов задач и выдачу новых cookie по IP. PostgreSQL по-прежнему принимает один голос на ID в каждой номинации. Анонимный режим ограничивает массовую накрутку, а разные браузеры и сети могут принадлежать одному человеку.

При смене режима сохранённые голоса остаются в БД. Анонимный ID и прежний аккаунт имеют разные идентификаторы. Если голосование по аккаунтам уже началось, участник с прежним голосом может проголосовать ещё раз с анонимным ID.

## Вход по email

Участник вводит email и восьмизначный код из письма. При первом входе сайт создаёт аккаунт, а следующие входы открывают тот же аккаунт с сохранёнными голосами. Старые аккаунты доступны по нику и паролю.

Сервис находится в `server/auth-service` и читает `server/.env`. Используйте настройки `AUTH_DB_*`, `AUTH_INTERNAL_SECRET` и `AUTH_SERVICE_URL` для подключения сервиса. Основной адрес сайта задаётся в `PUBLIC_ORIGIN`. Если открываете сайт через Vite, добавьте его адрес в `CORS_ORIGINS` и `AUTH_ALLOWED_ORIGINS`. Сайт и сервис вместе запускаются командой `npm.cmd start --prefix server`.

В `server/.env` задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` и адрес отправителя `SMTP_FROM`, затем перезапустите сервер. На порту 465 используется TLS с начала соединения. На остальных портах для внешнего SMTP требуется STARTTLS. [Параметры SMTP](https://nodemailer.com/smtp)

Код действует 10 минут, используется один раз и допускает пять попыток проверки. Один адрес может запросить письмо раз в минуту и до пяти раз в час. Один аккаунт может проголосовать один раз в каждой номинации. Владелец нескольких независимых почтовых ящиков может создать несколько аккаунтов.

Если сервис запускается отдельно, задайте `AUTH_AUTO_START=false` и используйте `npm.cmd run start:auth --prefix server`. При подключении сервиса даже в предпросмотре требуется вход. Без сервиса анонимное голосование доступно только при `start:bot-preview`.

## HTTP-защита

- Helmet включает CSP, защиту от встраивания сайта в чужие страницы и другие заголовки. HSTS включается, когда `PUBLIC_ORIGIN` задан с HTTPS.
- CORS разрешает `PUBLIC_ORIGIN` и точные адреса из `CORS_ORIGINS`. Для запросов регистрации, входа и выхода микросервис дополнительно проверяет `Origin` по `PUBLIC_ORIGIN` и `AUTH_ALLOWED_ORIGINS`.
- Общий лимит API — 240 запросов в минуту на IP. Запись голоса ограничена 90 запросами в минуту на IP и 30 на UUID участника. Запрос кода ограничен 12 попытками за 10 минут на IP.
- Вход по паролю допускает 10 неудачных попыток за 15 минут на IP и 30 на ник. Счётчики хранятся в памяти сервера, поэтому при нескольких экземплярах нужен общий лимит на прокси или общее хранилище.
- Указывайте `TRUST_PROXY=loopback` только при запуске за доверенным локальным прокси. Прокси должен перезаписывать входящие `X-Forwarded-For` и `X-Forwarded-Proto`. Это сохраняет отдельные лимиты для реальных IP.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/nominations` | Каталог номинаций со статусами и количеством номинантов |
| `GET /api/nominations?include=nominees` | Каталог с карточками номинантов и выбором текущего браузера |
| `GET /api/nominations/:id` | Номинация и `voted_nominee_id` текущего пользователя. В деморежиме выдаёт cookie с UUID, если её ещё нет |
| `GET /api/nominations/:id/nominees` | Номинанты |
| `POST /api/votes` | Принимает JSON `{"nomination_id":1,"nominee_id":1}` и cookie, возвращает `201` после записи |
| `GET /api/voter/challenge`, `POST /api/voter/verify` | Задача ALTCHA и выдача подписанной cookie в анонимном режиме |
| `GET /api/nominations/:id/results` | Результаты закрытой номинации. Для открытой и черновика возвращает `409` |
| `GET /auth/login`, `POST /auth/logout` | Публичные маршруты входа и выхода |
| `POST /auth/email/request`, `POST /auth/email/verify`, `POST /auth/sign-in` | Запрос и проверка кода, вход старых аккаунтов с паролем |

Успешные ответы под `/api` имеют форму `{ "data": ... }`, ошибки — `{ "error": { "code": "...", "message": "..." } }`.

## Архитектура

- `server/server.js` подключает роутеры API, входа и React, затем открывает HTTP-порт. Правила API находятся в `server/routes/api.js`, вход и выход в `server/routes/auth.js`, раздача сборки React в `server/routes/frontend.js`. Node загружает `server/.env` при запуске через npm.
- `server/routes` связывает URL с контроллерами и middleware. Контроллеры в `server/controllers` проверяют данные, выполняют параметризованные SQL-запросы через пул и формируют ответы. `server/middleware` обрабатывает ошибки, сессии входа и cookie предпросмотра.
- `server/database/db.js` создаёт пул PostgreSQL. `init.sql` задаёт схему, `seed.sql` содержит демоданные. При записи голоса транзакция удерживает блокировку чтения строки номинации до завершения записи. Уникальная пара `(user_id, nomination_id)` запрещает дубль, а составной внешний ключ проверяет принадлежность номинанта.
- `client` содержит интерфейс React, подключённый к API. Результаты запрашиваются для номинаций со статусом `closed`. Сервер также отдаёт файлы из `client/assets`, если этот каталог есть.

## Локальная смена статуса

В Query Tool pgAdmin или в `psql` выполните запросы к базе приложения. Подставьте фактический ID из первого запроса и нужный статус из `draft`, `open`, `closed`.

```sql
SELECT id, title, status FROM nominations ORDER BY sort_order, id;
UPDATE nominations SET status = 'closed' WHERE id = 1;
```

После изменения обновите страницу. В закрытой номинации можно посмотреть итоги на её странице. Повторное открытие сохраняет ранее поданные голоса.

## Границы прототипа

Сервер сайта и микросервис слушают `127.0.0.1`. Для внешнего доступа нужен HTTPS перед сервером сайта. Управление данными доступно через PostgreSQL. Административные HTTP-маршруты отложены.
