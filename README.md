# ITD Awards 2026

Участники входят через Telegram или регистрируются по приглашению и голосуют на сайте. Каталог, аккаунты, сессии, бюллетени и загруженные изображения хранятся в PostgreSQL. Telegram-бот выдаёт одноразовые коды входа на сайт.

| Папка | Назначение |
| --- | --- |
| `client/src/` | Публичные страницы и вход через Telegram на React, TypeScript и Vite |
| `client/admin/` | Веб-админка `/admin` и вход без Telegram `/account` на HTML, CSS и JavaScript |
| `server/server.js`, `server/routes/`, `server/modules/` | Запуск Express, подключение маршрутов и функциональные модули |
| `server/database/` | Подключение PostgreSQL, миграции, каталог и назначение первого администратора |
| `bot/main.py`, `bot/modules/auth/` | Запуск Telegram-бота, команды и запрос одноразового кода |
| `start.js`, `.env.example` | Совместный запуск и пример конфигурации |

Файлы и функции для типичных изменений перечислены в [CODE_MAP.md](./CODE_MAP.md).

## Запуск на Windows

Для настроенной установки достаточно `npm.cmd start` из корня проекта. Команда поднимает Express и после готовности его порта запускает Telegram-бота. Сайт открывается по адресу из `PUBLIC_ORIGIN`, обычно [localhost:5000](http://localhost:5000). `Ctrl+C` останавливает оба процесса. Перед переходом на эту команду завершите прежние экземпляры сайта и бота. На одном порту работает один Express, а один Telegram-токен использует один процесс polling.

### Первая установка

Установите Node.js 24, Python и PostgreSQL. В интерактивном `psql -h 127.0.0.1 -U postgres` создайте роль и новую базу. `\password` запросит пароль отдельно.

```sql
CREATE ROLE itd_app LOGIN;
\password itd_app
CREATE DATABASE itd_awards OWNER itd_app;
```

Из корня проекта выполните команды.

```powershell
npm.cmd ci --prefix client
npm.cmd ci --prefix server
python -m pip install -r bot/requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

В корневом `.env` укажите параметры `DB_*`, `PORT`, точный `PUBLIC_ORIGIN` без завершающего слэша, `TELEGRAM_BOT_USERNAME` и `BOT_TOKEN` из BotFather. Сгенерируйте отдельные значения для `BOT_API_TOKEN` и `AUTH_CODE_SECRET`. `VOTE_SALT` используется в автономном режиме бота. Для существующей SQLite сохраните прежнее значение.

```powershell
node -p "require('node:crypto').randomBytes(32).toString('hex')"
```

Примените миграции, импортируйте официальный состав и соберите клиент.

```powershell
npm.cmd run db:init --prefix server -- --official-catalog
npm.cmd run build --prefix client
npm.cmd start
```

### Существующая установка

Сохраните текущий `server/.env` с настройками PostgreSQL и авторизации. Чтобы бот из `bot/` использовал прежний токен и параметры, добавьте в корневой `.env` путь к его конфигурации. Для локальной установки путь уже задан.

```dotenv
BOT_ENV_FILE=../ITD_Awards/.env
```

Приоритет у переменных процесса, затем у корневого `.env`, затем у старого конфига компонента. Если перенесёте настройки в корневой файл, сохраните действующие `BOT_API_TOKEN`, `AUTH_CODE_SECRET`, `VOTE_SALT` и путь к SQLite. Удалите пустые переменные из шаблона, если значения для них берутся из прежнего `.env`. При `BOT_ENV_FILE` относительный `DB_PATH` считается от каталога прежнего бота. Без этого параметра он считается от `bot/`.

Сделайте резервную копию PostgreSQL. После обновления кода выполните `npm.cmd run db:init --prefix server`, `npm.cmd run build --prefix client` и перезапустите приложение. Для первого импорта официального состава закройте голосование и снимите результаты с публикации в админке, затем выполните `npm.cmd run db:init --prefix server -- --official-catalog`. В исходном списке 17 номинаций и 180 номинантов. Импорт сохраняет ID совпавших записей и голоса. Номинанты вне нового состава переходят в архив. Номинации, созданные вручную вне предоставленного списка, сохраняются. Если найдены несколько подходящих записей, весь импорт откатывается. Повторный запуск сохраняет последующие правки из админки.

### Обновление состава из семи файлов Telegram

Передайте каталог с исходными текстовыми файлами. Первая команда показывает план по подключённой PostgreSQL. Вторая строит план заново и применяет его в одной транзакции. Проверьте настройки подключения и план перед применением.

```powershell
npm.cmd run db:sync-nominees --prefix server -- 'C:/путь/к/спискам'
npm.cmd run db:sync-nominees --prefix server -- 'C:/путь/к/спискам' --apply
```

Скрипт сохраняет исходные ссылки, архивирует исключённых номинантов вместе с их записями и фиксирует изменения в `audit_logs`. Ошибки в списках и неоднозначные совпадения останавливают импорт. Повторный предварительный просмотр после применения должен показать пустой список изменений.

### Запуск по отдельности

- Сайт и API после сборки клиента — `npm.cmd start --prefix server`.
- Бот — `python bot/main.py`. В его конфигурации `AWARDS_SITE_API_URL` задаёт локальный адрес Express без `/api`, например `http://localhost:5000`. `BOT_API_TOKEN` должен совпадать с токеном Express. При совместном запуске `start.js` передаёт фактический порт сам.
- Vite с обновлением публичных страниц при правках — `npm.cmd run dev --prefix client`. Добавьте `http://localhost:5173` в `CORS_ORIGINS` Express. Если порт API отличается от `5000`, задайте `API_PORT` перед запуском Vite. Страницы `/admin` и `/account` открывайте по адресу Express.

Если бот установлен в виртуальном окружении, задайте `PYTHON` в корневом `.env` полным путём к его интерпретатору.

## Вход и Telegram

На `/sign-in` вводят одноразовый код, выданный Telegram-ботом или организатором. В личном чате `/start` и `/login` запрашивают код, `/newcode` запрашивает новый после минутного интервала. Код действует пять минут и используется один раз. Старый адрес `/account` перенаправляет на `/sign-in`.

Бот работает только для выдачи кодов. Предыдущие файлы автономного бота перенесены в `tash/bot`.

## Админка

Админ-панель открывается на `/admin`. Каталог, голосование, пользователи, приглашения и состояние сервисов доступны из бокового меню. Владельцу также доступны обзор базы, аудит и управление сессиями. Данные о нагрузке хранятся в памяти Express.

Подтверждение опасных действий требует удержания кнопки в течение секунды, в том числе с клавиатуры.

Владелец может просмотреть журналы и отозвать сессии. Правки данных выполняются через редакторы.

Первого владельца назначьте по его Telegram ID из доверенного терминала. Подставьте фактический ID из доверенного источника, затем войдите через Telegram и откройте раздел «Админка» или `/admin`.

```powershell
npm.cmd run admin:bootstrap --prefix server -- 123456789
```

| Роль | Доступ |
| --- | --- |
| Участник (`USER`) | Номинации и голосование |
| Жюри (`JURY`) | Доступ участника и настраиваемый вес голоса |
| Администратор (`MANAGER`) | Статистика, каталог, участники и жюри, приглашения, состояние сервисов и расписание голосования |
| Владелец (`SUPERADMIN`) | Права администратора, управление старшими ролями, правила голосования, публикация, результаты, CSV и полный журнал |

- **Обзор** показывает счётчики, графики и последние действия. В **Пользователях** можно найти аккаунт, проверить историю и факт участия, изменить роль в пределах своих прав или заблокировать доступ.
- В **Каталоге** редактируются номинации и номинанты, порядок карточек и статус. Можно загрузить PNG, JPEG или WebP до 5 МиБ и 4096 × 4096, указать адрес изображения или профиль участника. Если к записи привязаны голоса, используйте скрытие. Перенос номинанта в другую номинацию доступен до появления его голосов.
- В **Голосовании** настройте расписание и включите глобальный переключатель. Бюллетень доступен в открытой номинации внутри заданного интервала. При первом голосе фиксируются роль и вес. Владелец закрывает голосование перед публикацией результатов и может скачать итоговый CSV.
- **Система** показывает время проверки и состояние публичной сборки, Express, PostgreSQL и бота. Статус Telegram обновляется по heartbeat. **Журнал** хранит критические операции и открывается владельцу.

### Как пригласить члена жюри

1. В админке откройте **Приглашения → Создать приглашение**, укажите имя и выберите роль. Код действует пять минут.
2. Скопируйте код и ссылку на страницу входа из окна выдачи. Передайте их участнику лично.
3. Для повторного входа владелец проверяет личность участника, открывает его профиль в разделе **Пользователи** и нажимает **Выдать новый код входа**. Действие доступно для активных участников и жюри без Telegram. Оно сохраняет аккаунт, роль и бюллетени.

Перед применением миграции `007-unified-login-codes.sql` сделайте резервную копию подключённой PostgreSQL через `pg_dump` и проверьте архив через `pg_restore --list`. Примените миграцию существующей командой `npm.cmd run db:init --prefix server`, затем перезапустите приложение. Старые пароли и приглашения предыдущего формата перестают давать доступ. Для прежних участников без Telegram используйте повторную выдачу по их ID.

## Проверки на тестовых данных

Создайте отдельную локальную базу с именем, оканчивающимся на `_test`. Тесты создают и удаляют временные схемы внутри неё. Конфигурация приложения `server/.env` при этом не загружается. В URL укажите тестовые учётные данные и адрес `127.0.0.1`.

```powershell
$env:ITD_TEST_DATABASE_URL = 'postgresql://itd_test:test_password@127.0.0.1:5432/itd_awards_test'
npm.cmd test --prefix server
npm.cmd run lint --prefix client
npm.cmd run build --prefix client
```

Из `bot/` выполните `python -B -m unittest discover -s tests -v`. Тесты активного бота используют заглушки Telegram и HTTP, синтетические токены и `ITD_BOT_TEST=1`. Серверные HTTP-тесты проверяют выдачу кода, вход, сессии и повторное использование кода на отдельной PostgreSQL. Для действий в браузере используйте отдельный профиль.

## Развёртывание на Ubuntu VPS

Установите Node.js 24, PostgreSQL, Python и Nginx. Соберите клиент, установите зависимости сервера через `npm ci --omit=dev --prefix server`, настройте корневой `.env` и примените миграции. Используйте владельца приложения для миграций.

Для совместного запуска через systemd укажите корень проекта как `WorkingDirectory`, `NODE_ENV=production`, `Restart=on-failure` и в `ExecStart` абсолютный путь к npm с аргументом `start`. Укажите точный HTTPS-адрес в `PUBLIC_ORIGIN`, установите `TRUST_PROXY=loopback` и ограничьте права на файлы с секретами. Запускайте приложение под непривилегированным пользователем.

Создайте окружение `python3 -m venv bot/.venv`, установите зависимости через `bot/.venv/bin/pip install -r bot/requirements.txt` и укажите в `PYTHON` абсолютный путь к `bot/.venv/bin/python`.

В HTTPS-блоке Nginx проксируйте сайт и закрывайте внутренние маршруты бота. Перезаписывайте заголовки прокси.

```nginx
location ~* ^/api/bot(?:/|$) {
    return 404;
}

location / {
    client_max_body_size 20m;
    proxy_pass http://127.0.0.1:5000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Проверьте HTTPS, права файлов конфигурации и резервное копирование PostgreSQL. Для автономного бота также сохраняйте SQLite вместе с прежним `VOTE_SALT`. Сохраните `AUTH_CODE_SECRET` между рестартами, чтобы ранее выданные действующие коды оставались пригодными.

Для файлового хранилища используйте [инструкцию обновления, переноса и отката](./server/deploy/media-storage.md).

## Контент для утверждения

- Подтверждение списка номинаций, написания имён и ников, а также официальные ссылки на номинантов.
- Фотографии и изображения с разрешением на публикацию.
- Даты и часовой пояс голосования, дата церемонии и ссылка на трансляцию. Дату церемонии задаёт `VITE_CEREMONY_AT` в формате ISO с часовым поясом при сборке клиента.
- Подтверждение прав на фотографии и аудиофрагменты из каталога перед публикацией.
- Актуальные контакты, если они отличаются от уже указанных на сайте.
- Telegram ID первого администратора и согласованный коэффициент жюри.

Правила API и путь данных описаны в [ARCHITECTURE.md](./ARCHITECTURE.md).
