# Файловое хранилище ITD Awards

Оригиналы лежат в `images/` и `audio/`, WebP-миниатюры в `thumbnails/`. Имя состоит из SHA-256 содержимого и разрешённого расширения. Запись проходит через временный файл в том же каталоге и атомарное переименование. В PostgreSQL остаются MIME-тип, размер, связь с миниатюрой и прежние оригиналы. Связи с номинантами используют прежние адреса `/api/media/<id>` и `/api/audio/<id>`.

Express проверяет метаданные оригинала и размер файла. При наличии файла он потоково передаёт нужный диапазон или делегирует раздачу Nginx. Если файл пропал или имеет другой размер, приложение использует прежний оригинал в PostgreSQL. Для диапазона PostgreSQL возвращает часть `bytea`. В режиме хранения только на диске потеря файла без резервной копии приведёт к `503`.

Миниатюры создаются при загрузке или управляемом переносе. Максимальный размер — 720 × 720 без увеличения исходника. Дополнительное поле `thumbnail_url` возвращается при загрузке изображения и в публичном каталоге. `image_url` по-прежнему указывает на оригинал. Клиент может использовать миниатюру для карточки и оригинал для увеличения или в качестве запасного варианта.

## Настройки

| Переменная | Поведение |
| --- | --- |
| `MEDIA_STORAGE_DIR` | Абсолютный путь вне репозитория. Пустое значение включает хранение в PostgreSQL. Укажите отдельный каталог на постоянном диске. |
| `MEDIA_FILE_ONLY=1` | Новые оригиналы пишутся на диск без копии в PostgreSQL. При сбое записи загрузка отклоняется. По умолчанию файлы и БД пополняются параллельно, при недоступности каталога используется БД. |
| `MEDIA_NGINX_ACCEL=1` | Приложение выдаёт `X-Accel-Redirect` для доступных файлов. Включайте после настройки внутреннего маршрута Nginx. По умолчанию Express транслирует файл сам. |

Дайте пользователю приложения право записи, а Nginx — только чтение. Для POSIX группа файлов и каталогов должна подходить обоим процессам, например через выделенную группу и setgid на корне. Сервис создаёт каталоги с режимом `0750` и файлы с `0640` с учётом umask. Не предоставляйте доступ на запись к этому диску другим приложениям. Повреждение может сохранить исходный размер файла. SHA-256 проверяется при переносе и при повторной загрузке файла с тем же идентификатором. Обычная раздача проверяет размер оригинала. Проверку хешей следует включить в обслуживание и проверку резервных копий.

## Обновление приложения

1. Сделайте и проверьте резервную копию PostgreSQL. Для обновления уже работающего файлового хранилища сохраните также его каталог.
2. Установите зависимости командой `npm ci --omit=dev --prefix server`. Sharp нужен для миниатюр. Убедитесь, что npm установил платформенные optional dependencies и пакет загружается под используемой версией Node.
3. Примените миграции командой `npm run db:init --prefix server`, без флагов импорта каталога. Миграция добавляет метаданные и разрешает пустой `contents` у новых дисковых файлов. Старые `bytea` остаются на месте.
4. Запустите новую версию с `MEDIA_FILE_ONLY=0` и `MEDIA_NGINX_ACCEL=0`. Путь `MEDIA_STORAGE_DIR` можно задать сразу или позднее. Проверьте загрузку старого изображения, запрос первых 64 КиБ старого аудио и чтение каталога.
5. При желании включите gzip и HTTP/2 по [примеру Nginx](./nginx-media.conf.example). При локальном reverse proxy оставьте `TRUST_PROXY=loopback` в настройках Express. Для раздачи с диска настройте внутренний маршрут и проверьте конфигурацию командой `nginx -t`. После применения настроек включите `MEDIA_NGINX_ACCEL=1` и перезапустите приложение. Проверьте публичный `206`, возврат `416` для диапазона за концом файла, `Content-Range`, MIME и кеширование, а также `404` прямого запроса к `/_itd_media/`. Сохраните существующий TLS-блок и пользовательские заголовки Nginx.

## Перенос оригиналов

Запускайте отдельно от развёртывания, с настройками выбранной базы и хранилища. По умолчанию команда проверяет метаданные, SHA-256 исходных и имеющихся файлов, доступное место и печатает план. В режиме dry-run каталог и записи БД не меняются. В оценку места входит до 1 МиБ запаса на каждую ещё не созданную миниатюру.

```sh
npm run db:media --prefix server
npm run db:media --prefix server -- --apply
npm run db:media --prefix server
```

Применение проверяет записанные файлы и обрабатывает ошибки по отдельности. Сверьте поля `completed` и `failed`, затем проверьте публичные запросы. Повторный запуск пропускает исправные пары «оригинал и миниатюра» и восстанавливает повреждённый файл, если исправный оригинал есть в БД. Повреждённый исторический растр может сохраниться как оригинал, а ошибка генерации миниатюры будет указана в отчёте. Копирование не удаляет содержимое PostgreSQL. Если транзакция загрузки оборвётся после записи файла, на диске может остаться неиспользуемый файл с безопасным хешированным именем. Автоматической очистки нет.

Переключайте `MEDIA_FILE_ONLY=1` отдельно после проверки резервного копирования диска, свободного места и отката. Проверяйте запись и чтение нового изображения, миниатюры и аудио.

## Откат

1. Если проблема только в Nginx, выключите `MEDIA_NGINX_ACCEL` и перезапустите приложение. Express продолжит отдавать файлы и диапазоны.
2. Для отката к коду до файлового хранилища отключите `MEDIA_FILE_ONLY` и перезапустите текущий backend, чтобы новые загрузки снова попадали в PostgreSQL.
3. Если режим хранения только на диске использовался, оставьте диск подключённым к текущей версии и восстановите копии:

   ```sh
   npm run db:media --prefix server -- --restore-db
   npm run db:media --prefix server -- --restore-db --apply
   npm run db:media --prefix server -- --restore-db
   ```

4. Убедитесь, что последний план пуст, ошибок нет и в `catalog_images` и `catalog_audio` отсутствуют строки с `contents IS NULL`. При проблеме восстановите файлы из резервной копии и повторите проверку.
5. Верните прежний код. Добавленные столбцы можно оставить. Файловое хранилище и резервные копии сохраняйте до подтверждения отката.
