# Архитектура ITD Awards

Express обслуживает публичный React-клиент, страницы `/admin` и `/account` из `client/admin/` и API с одного адреса. Страницы управления написаны на HTML, CSS и JavaScript. `server/routes/api.js` подключает маршруты функциональных модулей из `server/modules/`. Именованные обработчики обращаются к PostgreSQL через общее подключение `server/database/db.js`. `npm start` запускает Express и Python-бота. Применённые SQL-миграции отмечаются в `schema_migrations`.

## Вход

1. React запрашивает `GET /api/auth/me` или каталог с сессией и получает ссылку на бота.
2. Обработчик `bot/modules/auth/handlers.py` берёт Telegram ID из личного сообщения. `bot/modules/auth/site_api.py` отправляет его в `POST /api/bot/code`. Express проверяет адрес соединения и отдельный Bearer-токен. Выдача сериализуется по записи пользователя. Новый случайный код заменяет старый, а PostgreSQL получает только HMAC. Код содержит 60 бит энтропии и действует пять минут.
3. `POST /api/auth/login` принимает код бота или администратора, атомарно помечает код использованным и создаёт сессию. Браузер получает случайный токен в HttpOnly SameSite-cookie, PostgreSQL хранит SHA-256 токена. В production используется Secure-cookie с префиксом `__Host-`. Сессия истекает через 14 дней. Выход отзывает текущую сессию, блокировка аккаунта отзывает все.
4. Запросы записи из браузера требуют разрешённого `Origin`. Повторные неудачные попытки входа ограничены по IP. Первое срабатывание лимита за окно записывается в аудит без кода и IP. Счётчики HTTP хранятся в памяти одного процесса, а ограничение выдачи кода хранится в PostgreSQL.

При выпуске приглашения администратор создаёт постоянную запись `users` с ролью `USER` или `JURY`. Telegram ID и пароль для такой записи не нужны. Выдача обоих видов кода использует `storeLoginCode` и одну запись `auth_codes` на пользователя. Вход выполняет `login`, который в одной транзакции вызывает `consumeLoginCode` и `saveSession`. Блокировка пользователя сериализует погашение, отзыв и повторную выдачу. `invitation_codes` хранит сведения об административной выдаче, а новые хэши в этой таблице не записываются. Владелец может повторно выдать код активному участнику или жюри без Telegram после проверки личности.

Оба способа выдачи используют общую таблицу `users`. Ограничение голосования применяется на аккаунт премии.

## Голосование

Express проверяет сессию, блокировку, состояние настроек, даты, номинацию и принадлежность кандидата. Он получает роль и вес из PostgreSQL. Транзакция удерживает блокировки записей пользователя, настроек, номинации и кандидата до записи. Уникальная пара `(user_id, nomination_id)` гарантирует один бюллетень. Составной внешний ключ `(nomination_id, nominee_id)` защищает принадлежность кандидата. Изменение выбора, если оно разрешено, сохраняет зафиксированный вес и роль.

Миграция сохраняет бюллетени от старой авторизации и браузерного режима. Эти строки распознаются по пустому `voter_role` и исключены из официального подсчёта. Новые голосующие привязаны внешним ключом к аккаунту сайта. Персональный выбор читается с сервера даже после входа с другого устройства. В профиле администратора доступны участие по номинациям и история действий без выбора кандидата.

Импорт `--official-catalog` сверяет точные имена, учитывает несколько известных прежних названий номинаций и сохраняет совпавшие ID. Записи вне списка скрываются с сохранением связанных голосов и личной истории. Бюллетени скрытых кандидатов остаются в PostgreSQL и продолжают занимать уникальную пару пользователя и номинации. Команда требует закрытого голосования и снятых с публикации итогов. При неоднозначном совпадении транзакция откатывается. Метка успешного импорта сохраняет ручные изменения при повторном запуске.

## Администрирование

Роли читаются из базы на запросах к `/admin` и административному API. Администратор `MANAGER` управляет участниками, жюри, каталогом и расписанием. Владелец `SUPERADMIN` управляет старшими ролями и полным журналом, правилами, публикацией и экспортом результатов. Административная запись повторно проверяет роль внутри транзакции. Изменение данных и запись в `audit_logs` фиксируются вместе. Связи в PostgreSQL защищают голоса при удалении и переносе кандидатов. Пока результаты опубликованы, API блокирует изменение каталога. Статистика и итоги используют сохранённый вес каждого бюллетеня.

Изображения загружаются с проверкой роли, сигнатуры, формата и размеров. Одинаковые файлы хранятся один раз в `catalog_images` по SHA-256 содержимого. Ссылка `/api/media/:id` отдаёт растровые байты с фиксированным типом из базы.

## Бот и состояние сервисов

При настроенном внутреннем API `/start` и `/help` читают актуальные номинации и доступность голосования по `127.0.0.1`. Запросы требуют отдельного Bearer-токена. Бот направляет пользователей на сайт, а `/admin` ведёт в веб-панель, которая проверяет роль по сессии. Команды прежнего Telegram-голосования доступны в автономном режиме `AWARDS_SITE_MANAGED=0`, который использует отдельную SQLite.

Бот передаёт состояние соединения с Telegram и время работы примерно раз в 20 секунд. Express хранит последнюю отметку и краткие коды недавних ошибок в памяти. После перезапуска сведения о боте появятся с новой отметкой. PostgreSQL проверяется запросом к серверу базы, а доступность публичной сборки определяется по её `index.html`. Проверка сборки измеряет состояние на сервере. Если Express или база сессий недоступны, административный интерфейс также может быть недоступен.

## HTTP API

Успех возвращает `{ data: ... }`, ошибка возвращает `{ error: { code, message } }`. Подробный каталог дополнительно возвращает состояние входа и голосования.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/auth/me` | Сессия и ссылка на бота |
| `POST /api/auth/login`, `POST /api/auth/logout` | Вход по одноразовому коду и выход |
| `POST /api/auth/invitations/redeem` | Совместимый адрес того же обработчика одноразового входа |
| `POST /api/auth/password/login`, `POST /api/auth/password/recover` | Возвращают 410 и адрес входа по коду |
| `POST /api/bot/code`, `POST /api/bot/status`, `POST /api/bot/catalog`, `POST /api/bot/heartbeat` | Внутренний API бота |
| `GET /api/nominations?include=nominees` | Каталог с номинантами, расписанием и личным выбором |
| `GET /api/nominations/:id`, `GET /api/nominations/:id/nominees` | Номинация и её кандидаты |
| `POST /api/votes`, `GET /api/votes/me` | Запись и чтение личных голосов |
| `GET /api/nominations/:id/results` | Опубликованный итог |
| `GET /api/admin/stats`, `GET /api/admin/catalog` | Общая статистика и управление каталогом |
| `POST /api/admin/nominations`, `POST /api/admin/nominees` | Создание записей каталога |
| `PATCH /api/admin/nominations/:id`, `PATCH /api/admin/nominees/:id` | Изменение и скрытие записей |
| `DELETE /api/admin/nominations/:id`, `DELETE /api/admin/nominees/:id` | Удаление записей без связанных голосов |
| `GET /api/admin/users`, `GET /api/admin/users/:id`, `PATCH /api/admin/users/:id` | Поиск аккаунтов, профиль, роли и блокировка |
| `GET /api/admin/invitations`, `POST /api/admin/invitations`, `GET /api/admin/invitations/:id/uses`, `POST /api/admin/invitations/:id/revoke` | Выпуск, история активаций и отзыв приглашений |
| `POST /api/admin/invitations/users/:userId/reissue` | Повторная выдача кода владельцем для существующего аккаунта без Telegram |
| `POST /api/admin/uploads/images`, `GET /api/media/:id` | Загрузка и чтение изображений |
| `GET /api/admin/system` | Состояние сервисов и недавние ошибки |
| `GET /api/admin/settings`, `PATCH /api/admin/settings` | Расписание, правила и публикация |
| `GET /api/admin/results`, `GET /api/admin/results.csv`, `GET /api/admin/audit` | Детальный подсчёт, CSV и журнал для владельца |
